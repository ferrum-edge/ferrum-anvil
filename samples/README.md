# Samples

Real output of the `anvil` CLI against the real core lab gateway (Ferrum Edge
v0.9.5 release binary on `127.0.0.1:18080`), regenerated by
`scripts/make-samples.sh`. `SOURCE.txt` records the commit, platform and time.
`crates/anvil-app/tests/samples.rs` checks that the workspace still imports and
the reports still parse.

| File | What it is |
|---|---|
| `workspaces/anvil-samples.anvil` | A portable workspace exported in "share" mode (no secrets). Six saved requests in three folders: a healthy call, three gateway-to-backend failures (refused, unresolvable name, body ended early) and two application errors that only look like gateway problems (a 500, and a 403 that is not a WAF). Import it with **Import → Anvil bundle / backup** or `anvil import samples/workspaces/anvil-samples.anvil`. |
| `reports/collection-run.{json,junit.xml,html}` | A collection run over every request of that workspace: one pass and five diagnosed failures. |
| `reports/load-report.{json,html,csv}` | A 200-iteration fixed load run (concurrency 4) over the healthy request, executed in the load worker. It is a smoke run on one machine, not a benchmark. |

The requests point at `http://127.0.0.1:18080`, so they only succeed or fail as
described while `anvil-lab up core` is running.

The sample workspace does not declare the lab gateway as a Ferrum Edge
integration profile. That is deliberate: the reports show how Anvil treats an
undeclared destination, where `X-Gateway-Error` is reported as an unverified
marker (`ferrum.marker.unverified`) and nothing is attributed to a gateway.
After you declare the gateway (Profiles → Ferrum gateway), the same requests
get gateway-attributed findings, capped at "likely".
